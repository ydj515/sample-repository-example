# Gemini 코드 리뷰 스타일 가이드

이 문서는 Gemini를 활용한 코드 리뷰 시 준수해야 할 스타일 및 가이드라인을 제공합니다.

## 1. 일반 원칙

*   **언어**: 리뷰는 항상 한국어로 답변합니다.
*   **응답 스타일**: 답변은 명확하고 간결하게, 전문가적인 톤을 유지해 주세요.
*   **명확성**: 코드는 읽기 쉽고 이해하기 쉬워야 합니다. 복잡한 로직에는 주석을 추가하여 설명을 돕습니다.
*   **명확성**: 코드는 읽기 쉽고 이해하기 쉬워야 합니다. 복잡한 로직에는 주석을 추가하여 설명을 돕습니다.
*   **일관성**: 프로젝트 내 기존 코드의 스타일(들여쓰기, 명명 규칙 등)을 따릅니다.
*   **간결성**: 불필요한 코드나 중복을 피하고, 가능한 한 간결하게 작성합니다.
*   **성능**: 성능에 중요한 영향을 미칠 수 있는 부분은 신중하게 검토하고 최적화를 고려합니다.

## 2. 코드 스타일

*   **들여쓰기**: 프로젝트의 표준 들여쓰기 규칙을 따릅니다 (예: 탭 또는 스페이스 2/4칸).
*   **명명 규칙**: 변수, 함수, 클래스 등의 명명 규칙은 프로젝트의 컨벤션을 따릅니다 (예: camelCase, snake_case, PascalCase).
*   **주석**: 
    *   코드의 *왜(Why)* 그렇게 작성되었는지 설명하는 데 집중합니다.
    *   복잡한 알고리즘이나 비즈니스 로직에 대한 설명을 추가합니다.
    *   TODO, FIXME 등은 명확한 설명을 포함하여 작성합니다.
*   **공백**: 연산자 주변, 괄호 안 등 적절한 공백을 사용하여 가독성을 높입니다.

## 3. 코드 리뷰 시 고려사항

*   **언어**: 리뷰는 항상 한국어로 답변합니다.
*   **응답 스타일**: 답변은 명확하고 간결하게, 전문가적인 톤을 유지해 주세요.
*   **기능적 정확성**: 변경 사항이 의도한 대로 작동하는지 확인합니다.
*   **에러 처리**: 예외 상황 및 에러 처리가 적절하게 구현되었는지 확인합니다.
*   **보안**: 잠재적인 보안 취약점이 없는지 검토합니다.
*   **테스트**: 변경 사항에 대한 테스트 코드가 충분히 작성되었는지 확인합니다.
*   **문서화**: 필요한 경우 관련 문서(README, API 문서 등)가 업데이트되었는지 확인합니다.

## 4. Gemini와의 상호작용

*   **명확한 프롬프트**: Gemini에게 코드 리뷰를 요청할 때, 어떤 부분을 중점적으로 검토할지 명확하게 지시합니다.
*   **피드백 활용**: Gemini의 제안을 검토하고, 필요한 경우 코드에 반영하거나 추가적인 질문을 통해 개선합니다.
*   **반복 학습**: Gemini의 리뷰를 통해 프로젝트의 코드 품질을 지속적으로 향상시킵니다.

## 5. 언어 및 프레임워크별 가이드라인

### 5.1. Kotlin

*   **코틀린 관용구**: 람다, 확장 함수, 데이터 클래스 등 코틀린의 관용적인 기능을 적극 활용하여 코드를 간결하게 작성합니다.
*   **널 안정성**: 널 안정성(Null Safety)을 최대한 활용하여 `NullPointerException` 발생 가능성을 줄입니다. `?` 및 `!!` 연산자 사용에 주의합니다.
*   **코루틴**: 비동기 처리에 코루틴을 사용하는 경우, 적절한 스코프 및 컨텍스트 관리를 확인합니다.

### 5.2. Java

*   **스트림 API**: 컬렉션 처리에 Java Stream API를 활용하여 가독성을 높이고 간결하게 작성합니다.
*   **Optional**: `Optional`을 사용하여 널(null) 값을 안전하게 처리하고 `NullPointerException`을 방지합니다.
*   **레코드(Records)**: 데이터 전송 객체(DTO)나 불변(immutable) 데이터 홀더에 Java 16+의 레코드를 활용하는 것을 고려합니다.

### 5.3. Spring Boot

*   **의존성 주입**: Spring의 의존성 주입(DI) 원칙을 따르고, 필드 주입보다는 생성자 주입을 권장합니다.
*   **어노테이션 활용**: `@Component`, `@Service`, `@Repository`, `@Controller`, `@RestController` 등 적절한 Spring 어노테이션을 사용하여 컴포넌트의 역할을 명확히 합니다.
*   **설정 관리**: `application.properties` 또는 `application.yml`을 통한 설정 관리를 일관되게 유지하고, 민감 정보는 외부화합니다.
*   **예외 처리**: `@ControllerAdvice` 및 `@ExceptionHandler`를 활용한 전역 예외 처리를 통해 일관된 에러 응답을 제공합니다.
*   **데이터 접근**: Spring Data JPA, Spring Data MongoDB, Spring Data Redis 등 Spring Data 프로젝트를 활용하여 데이터 접근 로직을 간소화합니다.
